# 路由判斷

`SKILL.md` 的 Step 1、Step 2 難以判斷時讀取本檔。

## 1. 輸出目標

| 情況 | 目標 |
|---|---|
| 使用者要求寫入、更新、補充某份文件 | Doc |
| Agent 正在編輯文件，且這張圖屬於文件內容 | Doc |
| 使用者要求「畫給我看」「解釋一下」，或 Agent 主動附圖輔助說明 | 對話 |
| 既要在對話中說明，又要寫進文件 | 兩者都做：文件中放 Mermaid；對話中只說明改了什麼，並視複雜度附 ASCII 或 HTML |
| 使用者只要 Mermaid 原始碼（例如要貼到別處） | 在對話中以 ` ```mermaid ` code block 提供，不產生 HTML |

拿不準時，預設為「對話」。寫入文件會改動使用者的檔案，必須有明確的意圖。

## 2. 交付環境

決定對話中 HTML 的交付方式：

| 環境 | 判斷方式 | HTML 交付 |
|---|---|---|
| 本機（Claude Code 等） | 可以讀寫目前工作目錄的檔案 | 寫檔後開啟瀏覽器 |
| 雲端 sandbox，有 Artifact 工具 | 工具列表中有 Artifact | 以 Artifact 發佈 |
| 雲端 sandbox，有傳送檔案的工具 | 工具列表中有傳檔工具 | 寫檔後傳送給使用者 |
| 都沒有 | — | 在對話中提供 ` ```mermaid ` code block，並說明可貼到 mermaid.live 檢視 |

本機優先：同時符合多種環境時，依表格由上到下選擇。

開啟瀏覽器失敗時（例如沒有圖形介面的遠端機器），不要重試其他指令，直接告知檔案路徑。

## 3. 複雜度計算

### 3.1 怎麼數

- **節點**：每個方框、決策點、資料庫、外部系統各算 1 個。起點與終點也算。
- **分支出口**：從同一個節點出發、走向不同節點的連線數量。
- **交叉線**：用最直覺的排列方式仍無法避免兩條連線相交。
- **回流**：任何指回前面步驟的連線，例如重試、返回修改、迴圈。
- **單一主軸**：整張圖能用「由上到下」或「由左到右」其中一個方向讀完。

### 3.2 各圖種的 ASCII 上限

| 圖種 | ASCII 上限 | 超過時 |
|---|---|---|
| 流程 | 節點 ≤ 5、出口 ≤ 3、無交叉、無回流 | Mermaid `flowchart` |
| 分層架構 | 層數 ≤ 4、每層方框 ≤ 3、只有向下的連線 | Mermaid `flowchart` + `subgraph` |
| 樹狀結構 | 深度 ≤ 4、項目 ≤ 15 | Mermaid `treeView-beta` 或 `mindmap` |
| 決策樹 | 深度 ≤ 5、終點 ≤ 15、每個條件 ≤ 4 個選項、無合流與回流 | Mermaid `flowchart` |
| sequence | 參與者 ≤ 3、訊息 ≤ 6、無 `alt`／`loop` | Mermaid `sequenceDiagram` |
| 其他圖種 | 不適用 ASCII | 直接用 Mermaid |

### 3.3 範例

| 說明內容 | 判斷 |
|---|---|
| 「請求進來 → 驗證 → 寫入 DB → 回傳」 | 4 個節點、線性 → ASCII |
| 「驗證失敗就回 400，成功就寫入，寫入失敗重試 3 次」 | 有回流 → HTML |
| 「Gateway 後面接 Auth 和 Core，Core 再接 DB」 | 3 層、每層 ≤ 2 → ASCII 分層架構 |
| 「6 個微服務之間互相呼叫」 | 節點 > 5、多半有交叉 → HTML |
| 「Client、API、DB 之間的 4 次往返」 | sequence 在上限內 → ASCII |
| 「訂單從建立到完成的 6 種狀態」 | 狀態圖不適用 ASCII → HTML |
| 「沒指定模型就用預設，有指定就查設定，查不到再試舊名稱」 | 巢狀條件、每條路徑各有結果、無合流 → ASCII 決策樹 |

## 4. 拆圖

符合任一條件就拆：

- 節點 > 15
- 包含 2 個以上彼此獨立的子流程
- 同時想表達「整體架構」與「某條路徑的細節」

拆法：

1. **總覽圖**：只放主要區塊與主流程，每個區塊用一個節點代表，節點數控制在 5–8 個。
2. **子圖**：每個需要細看的區塊一張，標題註明對應總覽圖中的哪個節點。
3. 每張圖各自回到 Step 2 判斷複雜度。總覽圖常常可以用 ASCII，子圖再用 HTML。

## 5. 同一段對話中的重複與更新

- 內容沒有變：不重畫，直接引用「前面那張圖的 [3]」。
- 內容有局部變動：重畫整張圖，並說明哪裡改了。HTML 檔案直接覆寫同一個檔名。
- 使用者要求修改圖：只改被要求的部分，保留原本的 ID 與方向，避免整張圖重新排版後難以比對。

## 6. 主動用圖的節制

主動附圖時：

- 一則回應最多主動附 1 張圖；需要更多張時，先附總覽圖，並詢問使用者是否需要子圖。
- 正在進行的任務（例如除錯、修改程式）中，優先用 ASCII 放在對話中，不要每次都開新的 HTML 打斷使用者。
- 使用者表示不需要圖時，這段對話中不再主動附圖。
