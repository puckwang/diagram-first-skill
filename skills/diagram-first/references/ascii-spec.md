# ASCII 規範

產出 ASCII 圖前讀取本檔。目標是在任何等寬字型、終端機、commit message、code comment 中都不會錯位。

## 1. 適用範圍

只在 `routing.md` 判定為「簡單」時使用，且只畫以下圖種：

| 圖種 | 上限 |
|---|---|
| 線性流程 | 節點 ≤ 5 |
| 分支／合流 | 節點 ≤ 5，每個分支點出口 ≤ 3 |
| 分層架構 | 層數 ≤ 4，每層方框 ≤ 3 |
| 樹狀結構 | 深度 ≤ 4，項目 ≤ 15 |
| 決策樹 | 深度 ≤ 5，終點 ≤ 15，每個條件 ≤ 4 個選項，無合流與回流 |
| 簡單 sequence | 參與者 ≤ 3，訊息 ≤ 6，無迴圈與條件區塊 |

超過上限就改走 Mermaid，不要硬畫。

## 2. 字元集

只用純 ASCII，不用 Unicode box-drawing（`┌ ─ │ ▼` 等），因為部分字型與終端機的寬度不一致。

| 用途 | 字元 |
|---|---|
| 方框角落、交會點 | `+` |
| 水平線 | `-` |
| 垂直線 | `|` |
| 箭頭 | `v` `^` `>` `<` |
| 樹狀分支 | `+--` `` `-- `` `|` |
| 決策樹分支、結果 | `+-` `` `- `` `|` `->` |
| 請求、回應（sequence） | `-->` `<--` |

## 3. 版型規則

1. **單一主軸**：由上到下（預設），或由左到右（僅限 ≤ 4 個節點的線性流程）。
2. **框寬統一**：同一層的方框寬度相同。框內文字靠左，左邊留 1 格空白，右邊至少留 1 格空白；橫跨多個子方框的寬框（例如 5.6 的上兩層）文字置中。
3. **框寬為奇數**：含兩側 `+` 的總寬度必須是奇數，中心欄位才唯一。
4. **中心對齊**：只有一個出口時，垂直連線從方框底邊正中央的 `+` 出發；箭頭 `v` 落在下一個方框頂邊的正中央。一個方框有多個出口時（例如 5.6 的 Gateway），每個出口的 `+` 必須對準下方子方框的中心。
5. **連線不交叉**：無法避免交叉就代表超出範圍，改走 Mermaid。
6. **不使用 tab**，行尾不留空白。
7. **方框之間至少空 1 行連線**，分支橫線另佔 1 行。

## 4. 標籤規則

- **框內只放 ASCII 字元**：編號加短英文，格式為 `[n] Name`，例如 `[2] Router`。
- **使用者語言的說明放在框外**：寫在方框右側（與方框中間那行同一行），或寫在圖例。
- 使用者語言是英文時，框內可以直接放完整英文標籤，但仍需編號以便圖例對應。
- 框內標籤 ≤ 20 個字元；超過就縮寫，完整名稱寫進圖例。
- 框外右側的說明寫在方框中間那行，與方框之間空 2 格，前面統一加 `<-`。

## 5. 樣板庫

每個樣板都已檢查過欄位對齊。使用時只替換文字，並依規則調整框寬：**加寬方框時，左右兩側要同時加寬，且所有連線的欄位要一起平移**。

### 5.1 線性流程（由上到下）

```text
+---------------+
| [1] Request   |  <- 收到請求
+-------+-------+
        |
        v
+---------------+
| [2] Validate  |  <- 驗證參數
+-------+-------+
        |
        v
+---------------+
| [3] Response  |  <- 回傳結果
+---------------+
```

### 5.2 線性流程（由左到右，≤ 4 個節點）

```text
+---------+     +---------+     +---------+
| [1] Get | --> | [2] Map | --> | [3] Put |
+---------+     +---------+     +---------+
```

由左到右時框外沒有空間放說明，說明一律寫進圖例。

### 5.3 二分支

```text
        +-------------+
        | [1] Check   |  <- 檢查權限
        +------+------+
               |
      +--------+--------+
      | yes             | no
      v                 v
+-----------+     +-----------+
| [2] Run   |     | [3] Deny  |
+-----------+     +-----------+
```

### 5.4 三分支

```text
               +---------------+
               | [1] Classify  |
               +-------+-------+
                       |
      +----------------+----------------+
      | low            | mid            | high
      v                v                v
+-----------+    +-----------+    +-----------+
| [2] Log   |    | [3] Warn  |    | [4] Page  |
+-----------+    +-----------+    +-----------+
```

### 5.5 分支後合流

```text
        +-------------+
        | [1] Check   |
        +------+------+
               |
      +--------+--------+
      | hit             | miss
      v                 v
+-----------+     +-----------+
| [2] Read  |     | [3] Load  |
+-----+-----+     +-----+-----+
      |                 |
      +--------+--------+
               |
               v
        +-------------+
        | [4] Reply   |
        +-------------+
```

### 5.6 分層架構

```text
+-------------------------------+
|           [1] Client          |
+---------------+---------------+
                |
                v
+-------------------------------+
|          [2] Gateway          |
+-------+---------------+-------+
        |               |
        v               v
  +-----------+   +-----------+
  | [3] Auth  |   | [4] Core  |
  +-----------+   +-----+-----+
                        |
                        v
                  +-----------+
                  | [5] DB    |
                  +-----------+
```

### 5.7 樹狀結構

```text
project/
+-- src/
|   +-- api/          <- HTTP handler
|   `-- db/           <- repository
+-- tests/
`-- README.md
```

- 子項目用 `+--`，同層最後一個用 `` `-- ``。
- 上層仍有後續項目時，以 `|   ` 延續；沒有時以 4 個空白延續。
- 說明統一對齊到同一欄，前面加 `<-`。

### 5.8 決策樹

一連串條件判斷、每條路徑各自走到一個結果時使用，例如設定解析、權限判斷、fallback 規則。任何路徑會合流或回到前面的步驟，就不是樹，改用 Mermaid `flowchart`。

```text
Request.Model 是否空白？
|
+- 否（有指定）-> ResolveRequestedModel
|     +- 系統設定找得到 -> 使用
|     +- 找不到 -> TryMigrateLegacyName（舊名稱遷移）
|     |     +- 有 -> 使用（輸出 DeprecationWarning）
|     |     `- 無 -> Reject NotFound
|     `- 不會改用使用者層級設定
|
`- 是（未指定）-> ResolveDefaultModel
      |
      +- GetUserConfiguredModelName
      |     +- 正式環境 -> 已發佈的設定快照
      |     +- 測試環境 -> 即時資料庫設定
      |     `- 值空白 -> null
      |
      `- ResolveWithFallback(ModelType, configuredName)
            +- 指定的模型存在且啟用 -> 使用
            `- null／已移除／停用 -> 系統優先度最高的模型
                  `- 系統無任何可用模型 -> Reject NotFound

最後：model.Enable == false -> Reject NotEnabled
```

- **條件節點用問句**，選項用「是／否」或具體條件值。
- **條件寫在節點上，結果寫在 `->` 之後**；結果之後還有判斷時，下一層接在該結果底下。
- **分支符號**：選項用 `+-`，同層最後一個用 `` `- ``。每深一層縮排 6 欄，上層仍有後續選項時以 `|` 延續，沒有時以空白延續。
- **終點使用固定詞彙**：同一張圖的終點只用幾個固定詞，例如「使用」、「Reject <錯誤碼>」，方便掃讀。
- **補充說明放括號**，不另開節點。
- **所有路徑共通的最後檢查**，在圖尾空一行後單獨寫一行，以「最後：」開頭。
- **節點文字可以用使用者的語言**：與方框不同，樹狀圖只靠行首的分支符號對齊，文字一律寫在符號之後，中文不影響對齊。分支符號仍只用 ASCII。

### 5.9 簡單 sequence

```text
 Client           API             DB
   |               |               |
   |-- request --->|               |
   |               |--- query ---->|
   |               |<-- rows ------|
   |<-- 200 OK ----|               |
   |               |               |
```

- 參與者名稱置中於 lifeline 上方，使用 ASCII。
- 每則訊息獨佔一行，標籤 ≤ 10 個字元，完整說明寫進圖例。
- 回應用 `<--`，請求用 `-->`。

## 6. 圖例

圖下方（code block 之外）用使用者的語言列出每個編號的說明，用一般 Markdown 清單，不受等寬限制：

```markdown
- **[1] Request**：收到使用者的 HTTP 請求
- **[2] Validate**：檢查必填欄位與格式
- **[3] Response**：回傳處理結果
```

框外右側已有說明，且說明已足夠時，圖例可以省略該編號。圖中有任何縮寫時，圖例不可省略。

## 7. 自檢程序

畫完後、送出前，逐項確認：

1. **垂直連線**：記下每條垂直連線的欄位編號（從 0 起算），逐行確認該欄位上的字元是 `|`、`+` 或 `v`，中間沒有斷開或偏移。
2. **方框閉合**：每個方框上下兩條邊的長度相同，左右的 `|` 與 `+` 在同一欄。
3. **中心點**：連線出發的 `+` 位於方框底邊正中央；箭頭 `v` 指向下一個方框頂邊正中央。
4. **分支橫線**：橫線兩端的 `+` 與下方各分支的 `|` 同一欄。
5. **框內字元**：沒有中文、日文、全形符號、emoji 或 tab。
6. **行尾**：沒有多餘空白。
7. **圖例**：每個編號都找得到對應說明。
8. **決策樹**：同一層的 `+-`、`` `- `` 與延續用的 `|` 在同一欄；每一行的分支符號都在文字之前；最後一個選項 `` `- `` 下方不再出現該欄的 `|`。

任一項不符合就修正後重新檢查。修正兩次仍無法對齊，改走 Mermaid。

## 8. 輸出格式

````markdown
一句話結論。

```text
（ASCII 圖）
```

- **[1] …**：…

需注意：…
````

依序為：

1. **一句話結論**：這張圖要表達的重點，而不是「下圖說明…」。
2. **ASCII 圖**：一律放在 ` ```text ` code block，避免 Markdown 解析空白與符號。
3. **圖例**（有編號或縮寫時）。
4. **例外或未核實項目**（有的話）：圖中省略的例外情況，或尚未從程式碼、文件確認的推測。
